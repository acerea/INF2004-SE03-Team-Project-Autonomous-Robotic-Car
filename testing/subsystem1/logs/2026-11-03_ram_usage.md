# Subsystem 1 RAM and size: minimum-bit representation (change requirement)

Build: Buddy-1 at `6a3ecdf` (firmware code identical to merge `09f2196`), `make NET=lwip MQTT=1 TEST=1`, sizes from `arm-none-eabi-size` on the object files.

Note: subsystem 1 was written bit-packed from its first commit (`227e948`), so no "before" build of this code exists. "Before" below is the natural C representation of the same fields (32-bit `int`/`uint32_t` fields, a struct of ints, or text), sized by the same rules.

## 3. Message buffers: what the same RAM holds

micro T-Kernel stores each message with a 4-byte length header and rounds the message up to 4 bytes (`kernel/tkernel/messagebuf.h`: HEADERSZ = sizeof(INT), ROUNDSZ).

| Buffer (RAM) | Message now | Bytes used | Fits | Natural message | Bytes used | Fits |
|---|---|---|---|---|---|---|
| g_mbf_telemetry (256 B) | flag + 8 B heartbeat = 9 B | 4 + 12 = 16 | 16 | flag + 52 B text = 53 B | 4 + 56 = 60 | 4 |
| g_mbf_cmd_raw (32 B) | 3 B | 4 + 4 = 8 | 4 | 26 B text (max) | 4 + 28 = 32 | 1 |
| g_mbf_remote_cmd (32 B) | 1 B | 4 + 4 = 8 | 4 | 8 B struct | 4 + 8 = 12 | 2 |

Because of the 4-byte header and rounding, saving bits below a 4-byte step does not reduce buffer RAM (a 1-byte command uses 8 B, the same as a 4-byte one). The gain is capacity: the same buffers hold 2x to 4x more messages.
